1 - хранение файлов с разной гарантией, сообщения при удалениии
2 - ценность продать не на уровне протокола - авто ранжирование ценности
3 - атака не так проста, не только захватить шарды, но и ждать, годы

4 - Кредит доверия (trust escrow)

Проблема: человек пришёл в систему, загрузил файлы, у него сразу умер диск.
Файлы попали в сеть, она может их хранить. Но отдать сразу — дыра в экономике
(загрузил → вытянул → ушёл, сеть потратила ресурсы бесплатно).

Решение: не отдаём, но и не стираем. Человек покупает новый диск, хранит
чужое, восстанавливает репутацию — в награду получает свои файлы обратно.

Механика:
- Upload всегда разрешён (данные раскладываются по сети, overhead минимален)
- Restore требует минимальный I-score: пропорционально объёму
  - Tier 1 (документы, <5 ГБ): I >= 0.1 (~1 мес работы)
  - Tier 2 (фото, <50 ГБ): I >= 0.3 (~3 мес)
  - Tier 3 (видео, >50 ГБ): I >= 0.5 (~6 мес)
- "Авансовый кредит": первый restore до 1 ГБ бесплатно (демо-эффект)
- Partial restore: документы раньше, видео позже (по tier)

Почему не стирать:
- Стирание штрафует честного невезучего пользователя
- Хранение стоит почти ничего (шарды уже распределены, ~3 ГБ на пира)
- Lock-in: "файлы в безопасности, ты должен заслужить доступ"

Обобщение:
- Любой restore требует минимальный I-score (не только после смерти диска)
- Это обобщение acceptance gate: gate = "не дадим хранить", escrow = "не дадим забрать"
- Вместе: gate + escrow = полный цикл защиты от фрирайдинга
- S-term из PI+S усиливает escrow: мало хранишь для других → низкий trust → дольше ждёшь restore

Связь с экспериментами:
- Exp 05: free-rider с 50% reliability неотличим от плохого честного → escrow закрывает дыру
- Exp 11: bootstrap в тёплой сети мгновенный → escrow добавляет "цену входа"
- Exp 13: Hoarder/Freeloader → S-term + escrow = двойная защита
