Масштабирование\n\n**Граф пиров O(n)** — каждый пир знает всех остальных? Из документа неясно, но placement engine должен знать trust для каждого потенциального holder. Если сеть 10000 пиров, а placement делает weighted sampling по trust² — это O(n) на каждый backup операции. Это работает при n=100, начинает болеть при n=1000, при n=10000 нужен routing layer.\n\n**Discovery и peer list** — документ упоминает \"peer_announce\". Как обнаруживается 10000 пиров? При n=1000 пользователях с похожим объёмом — relay пиры получают огромную нагрузку. Документ нигде не оценивает message throughput per peer.\n\n**Repair storms при входе/выходе** — документ говорит \"холодный бекап решает repair storm\". Это правда для churn отдельных пиров.
